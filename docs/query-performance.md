# 历史查询性能（2026-11-02 实现，随 0.2.4 发布）

[PR #17](https://github.com/cpython666/starclip/pull/17) 已合入 main（`b61206b`），并随 [0.2.4](https://github.com/cpython666/starclip/releases/tag/v0.2.4) 于 2026-11-03 正式发布。本轮在 SQLite 结构 4 上优化连续搜索、切换分类和翻页时重复执行的全局聚合。没有改变查询接口、每页 50 条、搜索匹配方式或数据迁移协议，也没有修改 Cloudflare Worker / 统计上报。

## 实现与一致性

`src-tauri/src/store/history_cache.rs` 在单个 Store 内保留一份全局分类数量、分组数量、来源、域名和标签选项。没有数据库变化时，后续查询复用这些汇总；所有页记录仍实时读取。没有搜索、来源、标签、隐私或 AI 限制的分类 / 分组查询还可复用匹配总数，其它条件仍执行完整匹配 COUNT。

- 版本戳同时检查本连接 `total_changes()`、其它连接提交的 `PRAGMA data_version` 和 DDL 的 `PRAGMA schema_version`。采用保守失效，普通偏好等无关写入也可能触发重算。
- 显式事务、活动 Rows 游标内清除并绕过缓存，未提交数据与回滚结果不发布；冷聚合在一个读事务内完成，提交读事务后再次核对版本才保留，防止将旧 WAL 快照标为新版本。
- 缓存估算保留预算 4 MiB，包含字符串字节及固定项开销；超预算仍完整返回全部选项，只是不额外保留。它不是分配量或进程 RSS 的硬限制，返回值仍会占用内存。
- 导入、清理、隐私 / 标签变更和外部写入由版本戳失效；新开、迁移或恢复后构造的新 Store 不带缓存。记录可读性与 AI 权限不进入缓存。

读事务只覆盖冷的全局聚合；整份 `history_page` 仍由多个查询组成，不保证其它连接并发提交时汇总与页记录属于同一快照。本轮没有将原接口扩展为全页原子快照。

`history_cache_tests.rs` 的 5 项原创临时数据库测试覆盖真实新增 / 删除 / 星标 / 永久保留 / 分组 / 标签 / 来源 / 导入 / 清理 API、隐私规则及重扫、事务提交 / 回滚、SQLite FAIL 部分写入、外部连接提交、活动 WAL 游标、DDL、重开 / 快照以及超预算完整选项集合。它们验证缓存复用次数与实际结果，并不读取应用数据目录或真实剪贴板。

## 对照方法

入口：`scripts/benchmark-history.mjs` 与仅测试构建启用、默认忽略的 `store/query_bench.rs`。脚本为旧提交建立独立 detached worktree，仅注入与优化版完全相同的基准模块及测试声明；源码与 harness SHA-256、固定 baseline、完整数据规模及每种结果指纹均需通过校验。两版使用各自独立 release 构建目录。

```sh
node scripts/benchmark-history.mjs --stage compile
# 编译完成并停止其它重负载构建后采样
node scripts/benchmark-history.mjs --stage measure
```

默认旧版为 `2c64c481caccad7b0e61c9fe2bf6e470365f75b1`，可用 `--baseline-ref` 显式指定；规模为 10,000 / 50,000 / 100,000 条，每场景先预热一次，再采样 20 次，报告中位数及 p95。基准实际调用完整 `Store::history_page`，计时结束后才替换 / 释放上一份响应；全部 `clips + history` 的 API 序列化 SHA-256 用于验证两版结果完全相同，内部不序列化字段不在此断言内。

数据为独立临时 SQLite 中的原创固定内容：80% 文本、10% 代码、8% 链接、2% 文件引用，20% 记录分配到 20 个分组；固定来源、61 个域名、手动 / 规则 / 应用标签，包含隐私与待扫描记录，不访问引用文件。没有图片 BLOB、大正文分布或实际采集事件。查询场景为普通首页、少量命中 FTS、两字短词、广泛命中 FTS、末页 OFFSET、标签及来源联合筛选、含标签的 AI 搜索。

首次读取和改标签后的首次读取另作单次观察，不混进连续查询样本。这里的“冷”只表示统计缓存为空或刚失效；造数已经预热 SQLite / 文件系统页，不能说是冷磁盘启动。完整查询采样先于独立原始 SQL 诊断，诊断分别量匹配总数、取页、全局数量和选项枚举，不能将这些数相加解释优化后执行时间。

所有结果、原始样本、编译和检查日志保存在忽略的 `artifacts/history-query-20261102.noindex/`，不将数据库或日志加入 Git。

## 本轮结果

运行环境为 macOS aarch64 / Rust 1.90.0。旧版固定为上述 `2c64c48`，优化版为测量时尚未提交、随后提交为 `2bcef07` 并经完整双平台 CI 通过的冻结源码，Rust / 构建输入快照 SHA-256 为 `acc56c0ca16b8f31d56d7330b8328b57dae10144f9b2fa317b7877b5f9671ffa`；harness SHA-256 为 `9c8a879e9cee7bcd9b3d46cb6bde7503c0ba632ae6499c96dee8be278d8bd670`。本轮两版 21 种连续查询及 6 种首次 / 变更后查询的完整响应指纹一致。

以下为完整存储查询中位数，单位 ms，箭头为旧版 → 优化版；每档每场景 20 次。统计缓存已预热，数据在各轮连续查询中不变化。

| 场景 | 1 万条 | 5 万条 | 10 万条 | 10 万条 p95 |
| --- | ---: | ---: | ---: | ---: |
| 普通首页 | 49.820 → 0.145 | 250.996 → 0.130 | 502.214 → 0.141 | 516.582 → 0.150 |
| 少量命中 FTS | 49.138 → 0.152 | 243.072 → 0.286 | 490.950 → 0.433 | 525.914 → 0.548 |
| 两字短词 | 55.939 → 7.435 | 279.234 → 34.713 | 564.240 → 75.104 | 601.903 → 87.343 |
| 广泛命中 FTS | 78.262 → 28.612 | 394.818 → 141.590 | 782.993 → 294.098 | 829.445 → 310.053 |
| 末页 OFFSET | 56.141 → 5.172 | 280.498 → 26.703 | 565.063 → 54.519 | 633.027 → 56.294 |
| 标签及来源 | 67.181 → 18.232 | 338.784 → 93.724 | 624.413 → 142.209 | 651.857 → 150.473 |
| AI 含标签搜索 | 85.238 → 33.698 | 422.481 → 173.955 | 877.718 → 366.490 | 968.293 → 403.253 |

10 万条的匹配数依次为 100,000 / 10 / 7,692 / 100,000 / 100,000 / 97 / 5,315；末页为第 2,000 页。首页和少量命中搜索主要消除了重复全局聚合，复杂搜索仍受实时匹配统计影响。

首次及写后重算是单次观察值，不能与上述 20 次中位数直接比较，也不能解读为稳定的冷读改善：

| 记录数 | 首次，旧 → 新（ms） | 改标签后首次，旧 → 新（ms） |
| --- | ---: | ---: |
| 10,000 | 116.266 → 45.831 | 53.488 → 47.340 |
| 50,000 | 245.934 → 227.993 | 251.105 → 225.913 |
| 100,000 | 503.088 → 480.778 | 499.542 → 488.210 |

旧版 10 万条的独立原 SQL 诊断中，全局数量中位数 98.260 ms、选项枚举 361.912 ms，说明反复枚举选项是主要重复成本之一。优化版同一原 SQL 诊断为 101.492 / 378.140 ms；它本身没有变快，收益来自在无变更时不重复执行。独立诊断还显示，10 万条宽泛 FTS 的取页约 204 ms，AI 含标签搜索的 COUNT / 取页各约 178 / 187 ms，两字短词 COUNT 约 72 ms，标签及来源 COUNT 约 91 ms，深页 OFFSET 取页约 54 ms。这些不是优化链路的相加分解；下一轮优先调查宽泛 FTS 的匹配与排序取页、AI 标签扫描，再按需求处理其余匹配统计、深页和后台调度。

## 验证边界与后续

本轮是 macOS aarch64 上的单轮完整存储查询对照，不包含前端渲染、IPC、Context 存储锁等待或用户可感知的完整响应时间，也没有用真实用户历史测试。平台构建和安装验收另见 [验证记录](verification.md)。

首次读取、每次写入后的首次查询仍需全局聚合。1–2 字符搜索、AI 含标签搜索与复杂筛选仍有扫描 / 实时 COUNT，深页仍为 OFFSET；大量图片、长正文、超大选项集合、连续采集写入和长期运行不在本次数据性能覆盖范围。下一轮应按实际占比处理剩余扫描 / 匹配统计与调度，不能据本轮连续查询提速承诺任意规模下的固定耗时或总内存。
