# 升级前内部备份与清理（开发分支，未发布）

2026-11-05 用户确认恢复点仅作为升级保护，不向用户开放。开发分支移除帮助页的恢复点列表、手动创建 / 还原、相应桌面命令和启动失败时的恢复点选择；升级和数据迁移仍先自动备份，再进行安装或事务升级。普通历史 JSON 导入导出与数据目录管理继续提供。

## 清理规则

- `before-update`、`before-migration`、`before-restore` 自动点的应用版本低于当前版本，或结构版本低于当前目标时，新版正常打开并校验当前数据库后即清理。这些旧版本副本取消最近 3 份与 7 天保护，逐级升级和跨版本直升都适用。
- 同一应用版本、同一结构的自动恢复点继续保留最新 3 份与最近 7 天内副本。升级安装失败后运行的原版本、当前会话刚创建的安装前快照按此规则保护，供重试使用。
- 历史手动恢复点保留，不再提供创建或还原入口。未来应用 / 结构 / 格式、无法识别的版本、未来时间、损坏清单、未识别文件、符号链接和文件大小不符的目录跳过。当前数据目录如果位于某份快照内，该快照受保护。
- 应用版本使用既有依赖 `semver` 比较，兼容正常的多段版本顺序及预发布编号。清理旧版本与同版本份数排序独立。

## 触发与失败

桌面应用成功打开存储、建立上下文后，在首次后台轮询（通常约 700 ms）尝试清理，之后每次运行中至多每 24 小时检查一次；暂停剪贴记录也检查。更新安装或目录切换等待重启时跳过，迁移失败时保留升级前恢复点。

出现删除候选后，先只读检查当前工作数据库的完整性、外键、结构与设置，并确认已达到当前结构版本，然后才删除旧副本。没有候选时直接结束。快照清单和文件元数据在删除前重新检查，快照内容的完整 SHA-256 校验仍在恢复时执行。删除失败通过数据管理页提示，下次维护重试，当前数据库继续使用。

删除的快照对应恢复时点随之失效。旧程序副本 `application-backups/`、历史手动点和用户导出备份保留。已发布 0.2.4 没有自动清理能力，本策略随包含该实现的新版本生效。

实现位于 `src-tauri/src/storage/recovery_cleanup.rs`、`storage.rs::recovery_inventory`、`desktop/clipboard.rs::monitor`；不再提供恢复点页面或相应调用权限。原创临时目录回归覆盖旧应用版本与旧结构近期副本立即删除、当前数据 / PNG / 资源保留、同版本规则、异常 / 未来 / 手动目录、校验失败与迁移失败保护、逐级和跳级升级后清理，具体结果见 [验证记录](verification.md)。
